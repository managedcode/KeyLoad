# ADR-134: Node-owned derived operational analytics

Status: Accepted; the native component is connected to the existing physical silo owner and administrator Dashboard. The new production path and public checks require execution; full Linux/RF3, resource, fault and performance qualification remain OPEN. Historical component-only Stage89 results retain their original scope.

## Selected package and authority

The owner selected published ZoneTree.Analytics1.0.0, original MIT copyright2026 Ahmed Yasin Koculu and native ZoneTree2.0.1 dependency. The verified package archive SHA256 is `14254385f46a979ddbfee6c874833b4a3a5e754655bdc39b0525d99262370452`; its nuspec source commit is `f7511306bbf0c375a918fc8a93845b1f596777b7`. Existing central pins, package reference and unmodified license asset are retained. No new dependency, local package or source replacement is introduced.

Derived analytics is disposable node-local operational history. Canonical ZoneTree models, database credentials, journals, RF3 acknowledgements and fresh persisted authorization remain authoritative. OpenTelemetry remains the native instrumentation baseline. TimeSeries aggregates are a separate database capability and do not prove that this package ran. Physical replica rollups must never be summed into cluster transaction counts.

## Actual native lifetime

The existing Orleans PartitionStorageGrainService opens the same PartitionHostApplicationOwner. Before opening a native analytics engine, its singleton OperationalAnalyticsRuntime is already published in DI and physical ownership retains that witness. After canonical recovery, the existing physical owner assigns its original PartitionHost, opens one native engine in `derived-operational-analytics`, reads the actual locked Consensus.StateAsync snapshot, submits its fixed numeric event and joins the native initial flush before publishing physical readiness. No second application host or independently managed silo exists.

Each admitted administrator Dashboard request takes one actual StateAsync snapshot and submits one native event, then reads the current UTC hourly rollup through the existing native owner. Sampling is demand-driven. The unused SampleInterval option and its periodic-policy fixtures are removed; unknown configuration fields remain rejected before native acquisition. There is no10-second background sampler, new scheduling platform, command/apply/WAL hook, or fabricated clock/provider. The library retains its original bounded worker/housekeeping implementation. Ordinary TimeProvider.System supplies observation time; original database log timestamps keep deterministic apply semantics. The former custom kernel/clock activation blocker is superseded by the root's2026-10-15 runtime ownership decision; this does not establish hard resource or physical quota qualification.

The existing physical close first joins connection work, native request/storage producers and transport. It then joins the original analytics request and native DisposeAsync before PartitionHost.DisposeAsync may release storage. An unknown native construction/close leaves CanReleasePhysical false and preserves the original physical/application witness. The original native owner retries supported remaining-resource cleanup once while preserving its first failure. HasJoinedEngine is set only after actual successful native cleanup. A canceled caller wait never proves that the original flush/query or file ownership ended.

## Public query and authorization

The existing admin.dashboard SDK method and official MCP tool remain the only public route for this report; their catalog size and signed connection execution path do not grow. Additive AdminNodeSnapshot field7 carries OperationalAnalyticsReport. The row/counters/report types have distinct stable generated Orleans aliases and field IDs. Existing field IDs0..6 are unchanged. A host adapter that does not supply analytics may return null; the selected server runtime must produce the report or fail explicitly.

The connection grain first reloads the current persisted principal and requires cluster-administrator authority. After the awaited Dashboard operation, it revalidates the signed request/call identity and reloads administrator authority again before returning the original result. Revocation, expiry and cancellation during the native wait cannot release a successful report to a stale administrator. No caller-provided role, custom expression, analytics filter or separate user store participates.

One existing Database.AdmitQuery reservation covers the original native state/flush/query task. The cancelable caller wait is separate; canceling it does not release the reservation early. The runtime retains the original task and rejects a second in-flight analytics read with ResourceExhausted. Native query timeout remains2 seconds; an original storage flush or cleanup join has no invented2-second deadline. Existing bounded native queue admission/loss and native first-failure ownership remain visible, without a replacement governor.

## Privacy, limits and report meaning

Only fixed site `keyload-node`, fixed event `replica-state-sample`, actual System UTC timestamp and three numeric values enter Track: committed_position, applied_position and committed_backlog. The adapter validates0 <= materialized <= committed <= last <=2^53-1 and computes backlog with checked integers. No principal, voter/leader identity, credential, query, document payload, URL, IP or private path enters an analytics event/report. Native logger text is not exported.

Raw events, sessions, visitor identification, geography, user-agent/version/query-string collection, web parsers/bot detection and custom dimensions remain disabled. Empty AllowedDimensions and zero custom dimensions are explicit. The query is native QuerySource.Rollups/FillMode.None, current UTC hour through next hour, Events plus the three fixed sums, without caller-shaped group/filter/metric expressions or raw fallback. Projection rejects unexpected plans/shapes, excessive rows and invalid numeric values, then checks serialized report size.

Existing engineering bounds remain queue64, buffered rows128, native groups192, buckets168, rows192, report65536 UTF8 bytes, mutable store4096 items and disk segment/partition16384 items; one native worker and one admitted native query/flush. Hourly retention is7 days, native retention checks60 minutes, query/flush policy2 seconds. These settings are not a measured RSS/disk-byte ceiling or performance result. Counters reset on a new engine process; persisted hourly rows may predate those counters. NativePlanComplete describes only native query planning, never complete sampled history, zero loss, a database cut or an RF3 receipt.

## Required execution and retained evidence

The existing Stage89 private component tests cover actual native ingestion/rollups, privacy, second-owner refusal, joined cancellation and two cold reopens under their original local scope. They do not prove the new selected server path. New functional qualification must use actual Aspire-owned single-voter and RF3 resources, successful SDK/official MCP writes, both administrator Dashboard clients, native nonempty hourly rows/counters, numeric conservation, persisted administrator revocation and unchanged canonical documents/receipts. The executing physical node identity and actual voter count remain in the enclosing Dashboard snapshot; quorum1of1 is not RF3 fault tolerance.

Original source/image/DLL/PDB/runtime receipts, native cleanup and resource/fault/endurance gates remain mandatory. Failed or unexecuted public checks keep OperationalAnalytics OPEN. No package presence, sampled position sum, TimeSeries aggregate, source review or local compiler result is benchmark/performance/production qualification. The owner-required ZoneTree-family reporting policy applies to confirmed reproducible upstream defects; the optional native host scheduling request in upstream issue1 remains a capability request, not a reproduced defect.
