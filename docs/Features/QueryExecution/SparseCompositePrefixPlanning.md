# KL049: complete sparse composite-prefix candidate planning

AC-QUERY-005/006 and ADR-010 require one authorized complete result for indexed and consented bounded full-scan execution, preserving explicit full-scan consent, persisted field-use, native read cut and complete response bounds. The canonical Documents.UpdateIndexes/IndexValues producer omits the whole composite entry if ANY field is null/missing under its IncludeNull/IncludeMissing policy. QueryCandidateReader.IndexPath previously selected a shorter nonempty equality prefix without considering omitted trailing fields: status=open over (status,rank) lost existing rows where rank was null or missing. Residual predicates cannot recover absent candidates. This is a source-proven KeyLoad planner omission, not an upstream ZoneTree defect.

Retain descending native index order and the original fully-bound nonnull equality rule. Admit a partial composite prefix only when BOTH IncludeNull and IncludeMissing retain all suffix states; otherwise continue to the next actual index. If none is complete, the existing AllowFullScan consent and configured bounded scan path apply; false consent retains the existing UnsupportedCapability refusal. No union/materialization, implicit scan permission, forced scan option, collation/coercion, broader predicate rewrite, budget or default change. Existing point, contradictory/mixed-type predicate semantics are unchanged and retain their independent criteria.

Four genuine Unit variants and four real Aspire RF3 SDK/official MCP variants each author the same independent seven-row corpus, two resources (composite alone and composite plus shorter complete status index), and all four include flags. Prefix matches include missing/null/matching/nonmatching suffix rows; full nonnull tuples match one or no rows. SQL, independent JSON AST and native C# builder each execute the indexed/eligible path and an equivalent repeated-OR predicate through the existing explicitly consented scan. Complete independently literal rows/order/metadata and access path are checked, never derived from an executed page. False consent refuses only actual fallback-to-scan and succeeds through complete candidate indexes. Fresh persisted Use removal denies the same queries, then same subject/credential repair restores them.

Native Unit phases preserve whole store image/position/identity after every response, independently authored full seed receipt, original outcome replay and two same-root cold owners. Public phases use original per-request Orleans SDK/MCP owners, full fourteen source documents through both clients, entire Outbox and original full seed receipt replay before/after each response, with original caller cleanup joined before each of two AppHost cold cuts. Public position is opaque; the captured original receipt is an authentic replay baseline plus independently authored full mutations/scope/epoch/durability, not an independently predicted initial physical position or no-op global counter. The existing original deadline is retained.
