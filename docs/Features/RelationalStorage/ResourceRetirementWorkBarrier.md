# Resource retirement: original-work barrier

This additive private stage separates D3 durable admission fencing from D4 publication settlement. D3 alone is not a work-join acknowledgement and does not permit D5 cleanup. Public DROP completion additionally depends on D5/D6 and the actual public coordinator.

## Original ownership and publication

The existing attached silo-local NativeRequestWorkOwner closes matching publication admission synchronously at the committed D3 fence. A publication admitted before this close may finish while its original producer drains. Cancellation and joining run outside storage, append, apply and owner locks. D4 does not promise network arrival ordering. A successful witness proves that the original matched readers, publication producers and cleanup tasks completed; ordinary original business/caller-cancellation failures remain in the local terminal report. Callback, enumerator disposal, release, join failures and fatal original failures prohibit acknowledgement. No raw exception enters a wire contract.

The attachment baseline is the maximum of the actual database LastApplied RF3 index and the original durable replica log State.LastIndex captured by the same node-local startup. Store.Position is a different counter and is never compared with a fence receipt. A new qualified closure requires a fence AppliedPosition strictly above this startup cutoff, the same physical owner and unchanged attached store node/read generation. This rejects pre-existing committed or uncommitted log entries replayed after attachment. Replaying an old fence can close current admission but cannot reconstruct earlier work as an empty successful observation.

A matching durable owner work acknowledgement is read in the same already-held Core view before the committed-fence hook runs. It suppresses a new close/resnapshot only after exact control/fence/owner validation. There is no permanent volatile closed-lifetime registry. Pending original closures and their terminal errors remain in the existing bounded owner until the exact handle is consumed after an actual durable owner acknowledgement. Capacity refusal and restart without an original closure or durable work record remain noncomplete.

## Private native read 10

Existing ResourceRetirementReadRequestV1 appends Id18 WorkFence and Id19 AcknowledgedWork. Existing reply appends Id10 WorkJoinWitness and Id11 AcknowledgedOwner. All old IDs, native purposes, global request kinds and MAC envelopes remain unchanged; old read branches reject the new arms. The authenticated async gateway performs the existing source RF3 barrier, persisted administrator admission, original expiry and exact native owner/voter/full-silo checks before invoking this read.

Capture reads the actual local durable owner work record first. If absent, it requires and awaits the same retained original closure. If present, it returns that exact stored acknowledgement and its original per-voter witness. A current native exchange authenticates the current destination voter/runtime; an old durable witness retains its historical silo/store generation rather than pretending to describe the restarted executor. Consume mode requires exact equality with the actual locally stored phase10 record and consumes only the matching retained handle; an absent original after restart is not replaced.

The witness contains the actual stored fence, physical owner, voter, full original silo address, store node/read generation, matched count, maximum original publication generation and a SHA256 digest. The digest input is ASCII `keyload.retirement.work-snapshot.v1` followed by one NUL byte and the native serialization of the original snapshot array sorted by AdmissionGeneration. Each stable generated snapshot contains RequestId, integer native work kind, AdmissionGeneration and LastPublicationGeneration. These are bounded original ownership facts, not persisted authority or user payloads.

## Durable phases

Phase10 CommitOwnerWorkJoin commits all actual owner-voter evidence through that owner's existing RF3 command path. Evidence retains the exact serialized existing signed native request and reply, including correlation and payload. Both MACs, canonical native bytes, complete reply shape, original fence and actual configured voter cohort are verified before issuance. Every original voter call is observed before complete cohort validation; there is no representative-voter shortcut.

Phase11 RecordOwnerWorkJoin records the exact owner acknowledgement at the source RF3 owner. Its body preserves constructor fields0/1 and appends Id2 DurableReads. The mandatory fresh all-voter signed read10 replies prove that the exact owner receipt is currently persisted. Only after this fresh authority proof are its original exchanges checked as historical signatures/correlation without renewing their old deadlines. Historical MACs alone cannot establish current durable authority. Fresh phase10 evidence always requires current original expiry.

The source rereads its actual state before constructing phases, so a lost phase11 reply reuses the stored source record instead of changing a deterministic command's body. A phase10 acknowledgement lost before source recording is recovered through the actual stored owner record, retaining its exact original evidence rather than minting new nonce bytes for the same phase10 command ID. All owner records are persisted at the source before consume attempts; retry can resume consumption without recapturing work. Phase12 SealAllWork commits the complete captured owner set at the source. D5 must validate this actual durable barrier and its local matching owner record.

## Bounds and qualification

The original expiry, configured native byte/record/result limits and original caller work budget apply. Voter reads receive bounded grants from that same work; returned counters settle those grants. Exact signed proof bodies consume real result/phase byte budgets. No timeout, size limit, quorum, timer, provider, host or RPC is added. A proof too large for the existing limits refuses rather than truncating evidence.

This source contribution does not qualify runtime D4, public DROP, cold recovery liveness, D5/D6 cleanup, RF3 fault handling or performance. Native compile/analyzer, genuine owner-origin/capacity/error flows, commit-before-apply restart, lost phase10/11 acknowledgements, revocation, cancellation, all-voter failover and public DROP/recreate gates remain separate requirements. Lower native test attachments must supply their own actual durable journal LastIndex; they may not fabricate a hosted startup baseline.

## Native pending-submission conservation

ReplicaLeader.SubmitOwnedAsync borrows the existing exclusive round owner and invokes ReplicaLeaderSubmissionReadCut.RequireAsync before AppendOwned. That helper captures the native durable LastIndex, requires a current-term quorum committed cut through that captured tail and awaits canonical apply. AppendOwned reads the retained outcome before a new append. An earlier journaled phase therefore materializes first or the later submission refuses; new nonce-bearing proof cannot overwrite the earlier entry. The admitted queue and original journal keep the original operation when a caller abandons its wait.

Phase10 always uses the exact original D3 sealed state read from its real stored seal outcome, including original fingerprint, principal/epoch, receipt and complete native state. It never strips later fields from an arbitrary current state. On a known native Conflict, phase10 reconciliation reads all current owner voters, validates their actual durable owner record and checks its entire original witness cohort against the originally captured witnesses. Phase11 similarly reconciles only the exact owner receipt found in fresh source RF3 state. Missing proof remains noncomplete, and an unresolved request never gains authority from a new empty snapshot or new MAC bytes.

Opaque UnknownWriteOutcome is deliberately not converted to same-call success: the existing exchange may wrap producer or cleanup failure as uncertainty. The original call retains that failure and remains noncomplete. A later same-command retry first reads actual durable records. Recovered known-conflict originals are returned in ResourceRetirementWorkBarrierExecution, a local-only receipt and exception vector retained by the owning DROP execution through terminal cleanup. Failure paths conserve all preceding original conflicts and every subsequent recovery/join error. The local report must never be serialized, persisted or treated as a rewritten parent failure when the actual business operation recovered successfully.

Native pending/lost-reply and commit-before-apply tests must use the existing real RF3 queue, durable log, barrier and fault ownership. A delegate-only simulated submit is not RF3 evidence. This source law and reconciliation implementation are not an observed runtime failure or a passing recovery qualification.
