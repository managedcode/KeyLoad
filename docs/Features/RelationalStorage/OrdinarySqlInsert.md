## Authority and atomicity

Within the original node-local transaction, current persisted DocsWrite, default/current row access, declared field writes and index-field use are checked, then authoritative schema and primary key are resolved. Existing resource policy CAS keeps nonpolicy schema and primary key immutable. Ordinary row insertion requires no cluster-administrator role. Any prior canonical row, including a tombstone or a row staged earlier in this same VALUES operation, refuses with Conflict. An absent row expands to the existing ExpectedRevision0 PutDocument, retaining its complete schema/index/outbox validation. A later duplicate, invalid scalar, missing required column or unique-index conflict rolls back every staged row. The original requested collection advances the existing document epoch; emitted outbox effects are canonical PutDocument.

Fresh typed permissions apply before outcome selection. Successful cached replay additionally checks current row/default access, fields and indexes, without absence/CAS re-execution. The same original request returns the complete saved success or failure; changed content conflicts; revoked permissions and advanced epochs fence old outcomes. A first failed operation may retain its existing failed outcome/clock. Subsequent replay must preserve that complete original outcome, full raw image and cut. No absence pre-read, identity synthesis, overwrite or resurrection is allowed.

## R61 actual published-receiver qualification boundary

The original R59 full native run retained two failed positive movement operations: `OriginalTypedInsertSurvivesRealRetirementCurrentPermissionFencesAndTwoColdOwners` and `ExplicitCallerFenceRetainsOriginalSqlAndInsertsAtPublishedOwnerAcrossTwoColdStores`. Both reached the current placement and retained original outcome assertions, then failed their first ordinary target `GetDocument` in `SqlTypedInsertRetiredAssertions.RowsAsync` with `OwnershipLost` from `RequireNoUnpublishedPartitionMoveTarget`. The native target still has its published movement stage. Ordinary target reads are deliberately fenced unless they execute inside the existing validated `PartitionControlResourceView`; publication alone does not authorize an unframed local receiver read.

The existing controlled document path captures fresh persisted principal/resource/publication authority at the source, validates the receiving frame and its read grant, and revalidates the source after receiving the result. Replacing the raw target read with a direct store read, deleting its stage, weakening its fence, or constructing an unchecked control view would hide the failure. A complete fix must preserve the original whole-operation identities, literal rows, SQL/AST checks, original receipt/outcome bytes, current permission repair and both cold owners, and must use the real authorized routing/execution contract for the healthy write and query continuation. The ordinary direct target SQL query and Batch continuation have not yet reached runtime in these two cases; their success must not be inferred from the earlier receipt checks. No repair or acceptance is claimed by this diagnosis.
