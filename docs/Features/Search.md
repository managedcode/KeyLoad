# Search

Search covers authorized text, vector, graph and hybrid retrieval over committed ZoneTree data. The delivery contracts of its children are [FilteredRetrieval](Search/FilteredRetrieval.md), [GraphRetrieval](Search/GraphRetrieval.md), [EventProjectionLineage](Search/EventProjectionLineage.md), [FullTextProjection](Search/FullTextProjection.md), [ManagedAnn](Search/ManagedAnn.md) and [OnlineGenerationLifetime](Search/OnlineGenerationLifetime.md). Index generations are disposable node-local storage state derived from canonical committed records; they are never an authority for acknowledged writes, authorization or replication. Distributed search is performed by Orleans grains that query the partitions through ordinary Orleans calls and merge the results; cluster concept: [ADR-136](../ADR/ADR-136-orleans-partition-ownership.md).

ZoneTree.FullTextSearch is the selected full-text provider under [ADR-071](../ADR/ADR-071-canonical-zonetree-providers.md) and the projection/freshness boundaries of [ADR-009](../ADR/ADR-009-search-provider-boundaries.md). Canonical-commit/index-generation freshness, tokenizer/hash/rank parity, nonpartial cancellation, authorization/read cuts, rebuild/rollback and resource bounds are frozen in [ADR-078](../ADR/ADR-078-full-text-projection.md). The provider's query language does not replace SQL.

| Requirement | Acceptance | Mapping |
|---|---|---|
| REQ-ZT-003: the selected full-text provider is a bounded derived projection | AC-ZT-003: the centrally pinned ZoneTree.FullTextSearch, an authorized exact token/identity/rank oracle, nonpartial cancellation and real replay/rebuild/swap tests on the Aspire replicated cluster pass; stale or corrupt generations cannot return success | Search provider tests, process recovery and SDK/official MCP tests |

## Resource contract for exact reads

| REQ-SR-006 | AC-MP-003/004/011/012: all analytical engines on one DatabaseEngine hold one counted reservation that never refuses a read; cancelled calls perform no ranking or storage work and release their reservation | Real-store mixed-entry admission/release cases in UnitTests/Features/ResourceExecution |

```mermaid
flowchart LR
    Caller --> Validate[Validate and prepare query]
    Validate --> Cut[Authorize within one read cut]
    Cut --> Corpus[Visit visible corpus records]
    Corpus --> Metadata[Keep bounded identity and rank statistics]
    Metadata --> Fusion[Exact branch ranks and fusion]
    Fusion --> Top[Select requested top results]
    Top --> Project[Budgeted selected point reads and projection]
    Project --> Output[Measure complete response]
```

The Core document-storage keys and the visible-document and visible-vector readers use the existing read view and one ReadExecutionBudget. Both visitor methods decode a single record, check persisted row visibility and invoke an owned-record callback without accumulating a full page; vector visits read each referenced document and reject stale/deleted/hidden candidates as before. The array-returning read helpers consume the same visitor algorithm. No callback may mutate the read transaction or escape the cut.

Text ranking retains lengths and query-term counts plus identities only for matching records; all visible documents still contribute corpus statistics. The text JSON pointer is compiled once. Vector ranking retains identities and scores, prepares the finite validation and cosine norm once, computes only the chosen metric and preserves the Vector.Widen/Vector.Dot/scalar-tail reduction grouping. Exact hybrid fusion requires bounded metadata for every ranked candidate (dropping branches to Limit before fusion is forbidden); a bounded top-result heap then selects final payloads. Final selected point reads trade at most Limit extra reads for removing full-corpus payload retention, stay inside the same read cut and the shared operation's cancellation and expiry. `DocumentStorageKeys.RecordKey` and `Prefix` supply canonical keys to both visitors and selected reloads.

REQ-SR-003/004/005 also fix the shared text/vector byte boundary: with two documents, a vector and lineage, the shared hybrid request must exceed the budget by its additional corpus document read, including the Resource key/payload and the absent BM25-head key in the arithmetic, while each isolated branch returns its complete literal records and ranks; limits are not raised and a healthy follow-up and a cold reopen keep complete rows and position. Coverage includes missing/empty text, Unicode, repeated terms, differing corpus lengths, same-score IDs, zero vectors, nonfinite values, dimension/space mismatch, stale revision, hidden/redacted fields, exact and excess byte/output/work budgets, cancellation and recovery of subsequent reads, on real ZoneTree with persisted policy. UI and data migration are N/A because the stored format and wire shape do not change.

## SIMD execution

REQ-SIMD-005: the normal product requires hardware-accelerated .NET SIMD. Core owns `Features/Search/Validation/SimdRuntime.cs` and the public `KeyLoad.SimdRuntime.RequireHardwareSupport()` admission. `System.Numerics.Vector.IsHardwareAccelerated` admits the supported CPU's .NET implementation; unsupported execution throws an explicit `PlatformNotSupportedException`. The server calls that admission before serialization initialization, configuration construction or node-local storage acquisition; standalone similarity validates its dimension bounds and then calls the same admission before vector validation. There is no scalar fallback and no SIMD disable selection; Vector finite blocks, Widen/Dot accumulation, bounded scalar tails, error order, authorization, read cuts, cancellation and the original metrics are preserved.

AC-SIMD-005 maps REQ-SIMD-005 to the VectorMetricValidationTests, VectorMetricGoldenTests and CanonicalVectorPublicMetricTests whole operations: every lane and tail keeps its finite/error result (NaN, +Infinity and -Infinity at every full-block lane and scalar-tail position; empty, 4097 and mismatched dimensions; query validation before invalid metric); lengths 1, the runtime vector width, width+1, two widths+1 and 4096 preserve the selected metric goldens, finite extremes and zero-vector handling; the three canonical metrics exercise a real complete block plus a bounded tail, full authorized pages, cancellation without effects and a healthy continuation. Only full finite-validation blocks use portable `Vector.Abs` and strict `Vector.LessThanAll(..., +Infinity)`; the length check, scalar `float.IsFinite` tail and all metric reductions are identical. Unsupported hardware is rejected rather than advertised as supported; no speed improvement is claimed without matched measurements.

REQ-SIMD-006: execution and qualification expose one normal SIMD-enabled profile; test selection rejects `unit-scalar` and inherited hardware/SIMD disable requests before launching a runner (AC-SIMD-006, `TUnitSelectionTests`).

REQ-EXECUTION-WAL-NORMAL-001 / AC-EXECUTION-WAL-NORMAL-001: the checksum-profile recovery test (`ChecksumProfileRecoveryTests.CurrentWalPreserves257RecordsAndBothAppendsAcrossFourProcesses`, no parameters) checks SIMD eligibility before opening its store and runs four real processes in seed, first-append, second-append and cold order; it retains the 257 corpus rows, both acknowledged command/receipt/outcome appends, original retry and conflicting-body refusal, complete persisted models/outbox, a byte-exact cold cut and the same-root identity. ## Controlled quality corpus

REQ-SEARCH-007 / AC-SEARCH-007 add a controlled first-party quality oracle under [ADR-018](../ADR/ADR-018-global-rank-fusion.md). The corpus has 32 literal documents, fixed four-dimensional vectors and six literal query definitions (English, Ukrainian, repeated and missing text, graph-only discovery, selective allowed IDs and an empty allowed set). Query definitions and relevance grades 0..3 are authored before execution and never derive from observed ranks; persisted grants and independently declared eligible IDs define each query's eligible set. The judgments describe the controlled fixture only, not an external evaluation dataset or a production relevance target.

Pass requires real node-local ZoneTree documents, vectors, graph edges and persisted authorization, using the actual `SearchEngine.GraphSearchAsync`, the BM25 `TextRanker`, the exact-vector branch, the graph retriever and the ZoneTree.FullTextSearch projection. and scalar-tail lexical parity preserves IDs, scores and stable order. Complete branches are captured with limit 32 only after seeding, all observations keep the same committed position and authority, complete candidate IDs match the independent eligible-set declarations, ineligible IDs are omitted, order is deterministic on repeat, an empty selection returns no candidates and missing branches contribute nothing.

The independent metric helper computes Recall@5/10, MRR@10 and graded nDCG@5/10 with gain 2^grade-1 and discount 1/log2(rank+1); a query without relevant eligible documents returns 0, duplicate ranked IDs are rejected, and hand-computed goldens (perfect/reversed rankings, missing relevant IDs, ties, empty input) verify the helper independently of production ranking. Every metric is finite in 0..1. Test-only window widths 1, 4, 8 and 32 per active branch truncate the real complete observations and run the actual `SearchRankFusion` kernel and `GlobalBranchWindowMerger`; width 32 reproduces the complete branch union and the production fusion, smaller widths expose truncation and candidate recall, and growing widths never lose union candidates. These controls expose no request-time window knob and prove no distributed global-ranking contract. When two canonical vectors have equal similarity their RRF contributions still differ (for example 1/61 and 1/62) because fusion is rank-based.

The finite hybrid task acceptance maps as follows.

| Criterion | Requirements and acceptance | Operations |
|---|---|---|
| Deterministic weighted rank and ordinal ties | REQ/AC-SEARCH-002; REQ-SR-001/004; REQ/AC-GSEARCH-003 | `ThreeWayHybridFusionTests`, `SearchTests.HybridFusionRanksEligibleDocumentsAndInvalidatesStaleVectors`, `ThreeWayHybridClusterTests` (SDK, official MCP, SearchSql and Q1 CALL) |
| Literal Explain, authorized metadata and bounded negative-to-healthy | REQ/AC-SEARCH-EXPLAIN-001/002/003; REQ/AC-SEARCH-003/004 | `HybridExplainWholeFlowTests`, `HybridExplainPrivacyWholeFlowTests`, opt-in Explain through SDK/official MCP/Q1 |
| Measured relevance-window effects | REQ/AC-SEARCH-007; REQ/AC-RANK-001..004 | `HybridQualityRealStoreTests`, `HybridQualityMetricOracleTests`, `GlobalBranchWindowMerge*` controls |
| Derived lexical recovery | REQ/AC-FTS-003/004/005; ADR-078 | `TextProjectionProcessRecoveryTests` process cuts and healthy rebuild |

The optional rerank hook is not part of the contract and no public candidate-window knob exists. A product window or scorer option needs its own ADR and API contract.
