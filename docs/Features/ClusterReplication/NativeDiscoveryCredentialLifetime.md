# Native credential lifetime correction

Parent NativeSiloDiscovery AC004, RecoveryNativeDiscovery AC003. Source defect: ReplicaMessageMac.Dispose zeroed its owned credential, but later signing computed MACs with the zeroed key and verification did not consistently refuse a disposed owner.

REQ-NATIVE-MAC-LIFE-001 / AC-NATIVE-MAC-LIFE-001: every cryptographic native authentication entry refuses an already disposed credential owner with ObjectDisposedException before field validation, digest, nonce admission or allocation. Actual native request/reply/discovery and typed native metadata methods retain their live bytes, purposes, canonical identities and validation.

REQ-NATIVE-MAC-LIFE-002 / AC-NATIVE-MAC-LIFE-002: the existing owned credential copy is cleared once and disposal is idempotent. A typed lock serializes the actual HMAC calculation against closure/zeroing; an original active HMAC either finishes with the exact original key or is refused, never calculates a mixed/zeroed key. Native runtime original joined shutdown remains the lifetime authority for admitted asynchronous work. No independent network or replacement owner is added.

Meaningful regression uses the Recovery genuine three-silo native fixture: create exact request, native reply and discovery proof while live, then dispose only scoped borrowed-auth owner and require actual Sign/Verify/refusal; closed runtime still refuses before the now disposed borrowed auth. Concurrent real native signing versus Dispose checks every returned signature equals the original exact signature and all later calls refuse. Caller credential bytes remain unchanged; original key-zeroing regression remains mandatory. These are source-only native boundary cases, not process-recovery/RF3/power-loss claims. Main compile, real native Recovery suite and Linux RF3 qualification remain open.

REQ-NATIVE-MAC-LIFE-003 / AC-NATIVE-MAC-LIFE-003: actual aggregate source audit must keep the canonical type200 bound. The existing main authentication plus native partial has 217 nonblank/noncomment source lines before this repair. Native purpose-frame/freshness/identity/reply ownership moves to a feature-local ReplicaNativeDiscoveryAuthentication helper borrowing the same existing authenticator, configuration, actual discovery state, freshness owner, MAC and voter set. Four existing internal entry signatures forward without changing their caller contracts. This is a cohesive native discovery responsibility split; the helper owns no key, network, lifetime or fallback and is not a new global layer. Original unsigned DTO/digest/domain frames, owned reply copies and exact error/MAC rules remain unchanged.
