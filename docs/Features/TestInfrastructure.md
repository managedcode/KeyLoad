# TestInfrastructure

TestInfrastructure owns how KeyLoad is verified. Tests are TUnit on Microsoft.Testing.Platform. The Aspire AppHost owns the Docker cluster resources, their readiness, test-runner dependencies, execution, scoped fault injection through Aspire-owned resource commands and joined shutdown. The cluster is configured by `KeyLoad:SiloCount` (Orleans silos) and `KeyLoad:ReplicaCount` (copies of each partition; 1 is the default and it never exceeds the silo count). A write is sent through ordinary Orleans calls to the ZoneTree owners of those copies and is acknowledged after every configured copy confirms durable local apply; membership, discovery, placement and activation movement belong to Orleans ([ADR-036](../ADR/ADR-036-orleans-foundation.md), [ADR-136](../ADR/ADR-136-orleans-partition-ownership.md), [ADR-143](../ADR/ADR-143-independent-silo-replica-topology.md)). Cluster tests drive the database through the real .NET SDK and the official MCP C# SDK client, and every owned resource is cleaned up.

## Scoped fault injection and container lifecycle ownership

All test container lifecycle and fault orchestration runs through the AppHost-owned resources and Aspire resource commands ([ADR-117](../ADR/ADR-117-tunit-ci-entry.md)). Test callers do not invoke engine CLI commands to run, start, restart, stop, kill or remove containers and create no independent cleanup containers. A genuine SIGKILL fault is a bounded command registered on the exact owned ephemeral test resource and invoked through `ResourceCommandService`; a graceful Stop is never substituted for it. Fault commands stay absent from ordinary product and comparison resources unless a separately authorized test-only composition selects them. The AppHost owns the selected resource identity, process and output-reader settlement, readiness, restart and shutdown; read-only container inspection may remain bounded identity evidence but is not lifecycle ownership.

## CI shards and lanes

[ADR-148](../ADR/ADR-148-parallel-ci-shards.md) defines the Build and Tests layout. `scripts/Features/TestInfrastructure/ci-test-shards.json` is the one manifest of shards; `ci-test-shards.mjs` reads it (`matrix`, `run`, `verify`, `inventory`), and its source scan (`ci-test-inventory.mjs`) needs no build. The Release workflow calls Build and Tests through `workflow_call` and publishes only after it succeeds.

| Job | Contents | Filter and concurrency |
|---|---|---|
| Build | governance, website source inventory, static shard partition check, `dotnet build KeyLoad.slnx -warnaserror` | none |
| Named functional operation groups | the namespaces listed for the shard | one process per namespace selected by its descriptive group ID, `/KeyLoad.FunctionalTests/<namespace>/*/*`, `--maximum-parallel-tests 10` on local and CI runners |
| Analyzers and process recovery | compiler analyzers, then process crash recovery | `/KeyLoad.AnalyzerTests/*/*/*` and `/KeyLoad.ProcessRecoveryTests/*/*/*` |
| Named cluster capability groups | one or two lanes per runner | each lane is its own `dotnet test` process, `--maximum-parallel-tests 1 --timeout 45m`, class or method alternation under `/KeyLoad.ClusterTests/*/` |
| Verify test partition | every shard's TRX artifact | `ci-test-shards.mjs verify TestResults` |

Every test job runs `dotnet build KeyLoad.slnx --configuration Release -warnaserror`, because tests read compiled outputs of projects their test project does not reference: ProductionSourceManifestOperationTests reads the image of every solution project, and ColdBootstrapSdkTests launches the CLI from the selected configuration. Local development uses the SDK default Debug configuration. Each job writes original TRX reports below its test assembly's `bin/Release/net10.0/ci-results/<suite>/<shard>/<lane or namespace>` and uploads them even when tests fail. The filters pin the assembly segment, so process recovery tests registered by the functional host run only in the process crash recovery shard.

The manifest balances whole test classes across thirteen cluster jobs and twenty-five lanes using original Linux case durations. Lane isolation kinds and the two-cluster bound stay explicit; browser classes retain their browser-enabled runner. Additional jobs can wait for runner capacity, so this layout balances the existing lanes instead of depending on twenty cluster jobs being admitted together. Actual wall time requires a complete Linux run of this partition.

A lane runs one test at a time, so it holds at most one 3-node cluster at a time and a 4-vCPU runner holds two. Lane kinds keep that bound: `shared-readers` and `shared-exclusive` lanes use one keyed shared cluster and create no clusters of their own; `own-clusters` and `functional-gate` lanes use no shared key; `isolated-clusters` lanes hold the other keyed clusters and tests without a cluster. Each lane process has its own keyed shared cluster, so a test that kills or restarts nodes affects only its own lane. Playwright is installed only on the shards that the manifest marks `playwright`.

The official MCP test client pins the requested protocol revision. Discovery uses the SDK's existing overall initialization timeout and the original caller token. The separate short detection probe is disabled through `DiscoverProbeTimeout = Timeout.InfiniteTimeSpan`, so a slow discovery response during a real silo fault is governed by that existing initialization budget. Protocol validation and the complete SDK/MCP result assertions remain required.
