# Atomic WAL acceptance

Goal: commands.wal serializes ordered mutations with native Orleans generated binary codecs, removing JSON/Base64 overhead while preserving atomic durable storage contracts. Actors: node-local PartitionHost/ZoneTreeStore only; callers retain unchanged SDK/MCP APIs, authorization and RF3 commit boundaries. In scope: private codec/DTOs, frame accounting, journal recovery, identity guard, tests and StorageRecovery docs. Out of scope: native ZoneTree byte serializers, replication journal, checkpoint2 payload format, model record encoding, grain topology and unrelated working-tree changes.

Assumptions: KeyLoad is the intended repository; only it contains ZoneTree. User was informed and optional clarification offered. Orleans10.3.1 is already pinned; direct Serialization reference uses that existing version. Upgrade is offline/homogeneous with verified pre-upgrade backup. No JSON compatibility decoder or mixed-version writes.

- AC-WAL-001 / REQ-STORAGE-015: new commits use stable generated Orleans DTOs/Ids/Aliases and a reused typed serializer. Binary persisted mutations reopen exactly, including binary keys, null deletion and empty live values. Native raw-byte storage remains unchanged.
- AC-WAL-002 / REQ-STORAGE-016: actual complete binary payload length governs MaxFrameBytes. Exact limit passes; one byte less rejects before durable bytes/position/state change. Repeated ValidateCommit caches, replacement/deletion invalidates, Reset clears, and rejected Stage preserves prior prepared state.
- AC-WAL-003 / REQ-STORAGE-017: checksum, complete payload consumption, supported magic, sequence, ordered unique nonempty keys and explicit Put/Delete kind/value pairing are checked before applying a frame. Malformed complete payload yields Corruption; legacy JSON yields FormatUnsupported. Current binary torn final header/payload retains existing truncation semantics. A full legacy52-byte header always refuses without truncation even if its payload is torn; shorter-than-header tails retain the existing rule. Never report fsync/kill as power-loss proof.
- AC-WAL-004 / REQ-STORAGE-018: new store identity3 fences old writers. Legacy empty/checkpoint-only identity1/2 recovers and promotes3 without changing logical bytes, incarnation, position or scope. Legacy JSON WAL refuses upgrade without rewriting/truncating its journal. Compact/InstallSnapshot/backup restore retain identity3 and existing checkpoint2 interoperability.
- AC-WAL-005 / REQ-STORAGE-019: restore/build/analyzer/format/governance and exact-source GitHub unit/process-recovery/Docker-Aspire RF3 tests all pass with real dependencies and no weakened/skipped assertions. Measured acceleration remains unclaimed until comparable GitHub metrics exist. Coverage gaps are explicit.
