02 / METHODOLOGY

Evidence before conclusions.

Read the methodology ↗
01

The same inputs.

A seeded corpus fixes document bytes, float32 vectors, graph edges and request schedules. Each engine gets the same warmup, concurrency and operation count. The corpus hash is recorded.

02

The full command path.

Clients call real services. Engines run sequentially, and order rotates between repetitions. Queue cycles include enqueue, receive and ACK. Setup and validation stay outside the timer.

03

Correctness comes first.

Writes are read back. Exact search matches an exhaustive cosine oracle. Graph results match a reference breadth-first traversal. Queue completion rejects missing, duplicate and wrong-payload messages.

QUALIFICATION STATUS

A development benchmark, with the limits visible.

Closed-loop loads and small datasets describe development behavior. CPU, allocation and RSS measures cover the load generator, including drivers and sampling. Database resource budgets and independent failure domains remain unqualified. Graph APIs share reachable-ID semantics; KeyLoad additionally transfers vertices and edges.
