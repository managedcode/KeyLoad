The database for AI agents.

One database for AI agents: documents, typed tables, graphs, blobs, queues, events, vectors/search and time series connected through canonical entity references. SQL is the familiar shared language; agents use the built-in MCP server and services use the typed .NET SDK.

  • MCP built inAgents query, read and write through the official MCP server, under the same permissions.
  • Policy in the databaseCredentials and authorization live server-side; callers cannot claim trusted roles.
  • .NET 10 · Orleans · RF3Three replicated voters per database with node-local storage.

Data that works together

Connected data. One request.

Tables, collections and queues organize one database. An agent can follow entity references across models and write the result through the same persisted permissions.

  1. 01

    Queue to knowledge graph

    Read ready messages, resolve their linked entities and write knowledge-graph relationships inside the database.

  2. 02

    Graph to queued actions

    Follow visible relationships to enqueue actions carrying canonical entity references.

  3. 03

    One authorized atomic command

    Source and target resources share the same atomic partition and transaction domain. A failed effect rolls back the whole command. Projection does not lease or ACK messages. Blobs remain part of the same database; staged upload and publication use their existing operations outside this initial graph/queue batch.

SDKThe same atomic CommandRequest

[
    new QueueToGraph("knowledge", "inbox", "fact-"),
    new GraphToQueueMutation("actions", "knowledge",
        start, "action-")
]);
(await client.CommitAsync(command)).ThrowIfFail();

The source adds this initial bounded procedural composition stage through SQL CALL, the .NET SDK and official MCP, with exact-source qualification pending. Full declarative SQL, the native SQL-client protocol and cross-partition composition remain required and pending.

Anatomy of one agent call

One tool call. One atomic commit.

The MCP server and the .NET SDK reach the same engine, the same persisted permissions and the same transaction rule.

  1. 01

    The agent calls a tool

    An MCP tool call or SDK command arrives with a credential the database verifies against its own stored policy.

  2. 02

    A grain takes the request

    Every request runs in its own Orleans grain, which invokes only the database grains it needs.

  3. 03

    The partition commits atomically

    The document, its event and the follow-up job are written together, or none of them are.

  4. 04

    Three voters replicate it

    The commit passes the ordered apply gate of an RF3 group of node-local PartitionHosts.

MCPAgent · tool call
tool  keyload_query_execute
input {

SDKService · .NET, one atomic command
var command = new CommandRequest(commandId, partition,
[
    new PutDocument("orders", "order-1", orderJson, ExpectedRevision: 0),
    new AppendEvents("events", "order-1",
        [new("event-1", "OrderCreated", eventJson)],
        ExpectedStreamRevision.NoStream),
    new EnqueueMessage("jobs", "message-1", jobJson)
]);
(await client.CommitAsync(command)).ThrowIfFail();

Built on .NET 10 and Orleans

A grain per request. Storage that stays home.

Orleans routes every request through its own grain and a distributed grain directory. Logical partitions stay distinct from physical placement: routing activations can move, while ZoneTree storage, journals, file locks and the ordered apply gate stay with each node-local PartitionHost.

Activation-migration qualification is still in progress.

Methodology

How we measure.

Read the benchmark methodology ↗
  1. 01

    Shared inputs

    A seeded corpus fixes document bytes, vectors, graph edges and request schedules. Workload conditions and corpus hash travel with each report.

  2. 02

    Real command paths

    Clients call real services. Setup, warmup and correctness checks are outside the timer; queue cycles include enqueue, receive and ACK.

  3. 03

    Correctness first

    Writes are read back, graph results match a reference traversal, and queue completion rejects missing, duplicate or wrong-payload messages.
