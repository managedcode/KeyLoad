# BenchmarkComparisons acceptance

Goal: reproducible nine-engine single/replicated comparison profiles, truthful GitHub JSON/SVG publication and a clear README/site. The owner authorizes these engine dependencies, shared scenarios and publication; no Enterprise activation, fake cluster, skipped correctness check or fabricated performance result is permitted.

Flows: fresh cluster initialization, supported workload repetitions, client concurrency, full readback, unsupported engine/scenario, failed replication acknowledgement, native query error, timeout/cancellation, duplicate/wrong event, bad JSON/provenance, missing artifact and wrong source revision. Engine startup/seed/warmup are excluded from measurement. Client CPU/allocations/RSS are labeled client resources; no false server-wide measurement is claimed.

Migration adds engine clients and new report fields without changing product persistence/API contracts. Existing benchmark sources move into the named feature paths only when their owner can verify the whole move; new code must use Features/BenchmarkComparisons. Rollback disables the newly qualified profile/publication without deleting immutable historical evidence or weakening existing gates. Business schema changes outside isolated benchmark datasets are out of scope.

All runtime tests and performance measurement run in GitHub Actions. Current successful baseline is 36926803549 at 9c570f8c33a7a9667507a8e1c0ca68860de3be45 with six engines; it is not nine-engine/fully-Docker qualification. Coverage/complexity gates must be truthful about configured evidence. Rendered UI proof is manual evidence in addition to automated data correctness.
